Entry page

Start here

This site documents one practical problem: how a long-lived AI system can act, remember, adapt, and use tools without turning fluent output into unchecked authority.

The smallest example is simple. If an AI worker can inspect files, edit code, run tests, or prepare a release, it must not also define its own permission, approve its own work, write directly into memory, or erase the evidence of what happened. A governed task therefore needs a contract, a sandbox or worktree, a witness record, a review path, and a rollback boundary before the result can become part of the system.

That pattern scales upward. The same distinction appears in memory, identity, continuity, self-evolution, public claims, and AI Act transparency: output is not evidence; evidence is not authority; continuity is not personhood; local operation is not sovereignty.

For engineers

Start with the executable-worker problem. CGAM treats CLI/cloud agents as bounded workers: they may inspect, patch, test, compare, and report, but they must not become will, memory, authority, judge, or release power.

Recommended path:

Note: L4 here means Reality Boundary Layer — power, heat, latency, maintenance, scarcity, and irreversibility. It is not SAE Level 4 autonomous driving.
