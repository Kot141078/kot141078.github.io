Overview

Mapped composition over anchor classes

A6 Composition Layer v0.1.1 is a protocol profile for hybrid and federated anchor composition in the c = a + b framework. It addresses cases where a deployment crosses clean anchor boundaries: human plus organization, family plus business, cross-lab research, federated clinical systems, multi-robot operational systems, and cross-border projects.

A6 Composition Layer v0.1.1 formalizes A6 as an anchor-composition state over A0-A5, not as a merged super-anchor. It defines hybrid and federated anchor composition for the c = a + b framework, including standing, authority, memory compartments, sensor boundaries, jurisdiction maps, Experience Artifact rules, resource/custodian responsibility, exit, split, witness, and fail-closed discipline.

Why A6 exists

Connection is not merger

A6 exists because real deployments often connect multiple anchor classes. The risk is not technical connection itself. The risk is treating technical federation as if it created one merged subject, one merged authority, one merged memory, or one merged identity.

Core rule: A6 may connect anchors. It must not melt them.

Core rules

Exit, split, and publication discipline

A6 is not a merged super-anchor.
A6 is a mapped composition over A0-A5.

A6-EXIT = revoke-and-continue.
A6-SPLIT = freeze-and-escalate.

Map first.
Compose second.
Externalize last.

What changed in v0.1.1

Composition correction

The release distinguishes A6-EXIT from A6-SPLIT, adds mandatory maps for standing, authority, memory compartments, sensors, jurisdiction, Experience Artifacts, resource/custodian responsibility, and keeps externalization last.

It keeps A6 framed as mapped composition over A0-A5, not merged standing, memory, identity, or authority.
