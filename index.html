Public map

A public map of a long-lived local AI system

For more than three years I have been running Project Ester as a long-lived local AI system rather than a chatbot demo. The current setup includes three separated c trajectories on dedicated machines, with operational traces, review records, and witness-compatible logs kept outside the public site.

The protocols published here — c = a + b, L4, SER, CGAM, Self-Evo, witness, rollback, and memory-gate layers — were developed from that operating context and then formalized into DOI-bound public packages, release tags, manifests, and checksum records.

This site is the public map of that work. It does not expose private memory, raw dialogue, credentials, runtime secrets, or the live entities themselves. It exposes the architecture, evidence boundaries, publication trail, and reviewable materials needed to inspect the work without violating the system.

Entry routes

Three ways in

For policy readers

Start with the Article 50 transparency materials. They map the architecture onto AI Act transparency, evidence, disclosure, provenance, and responsibility boundaries.

Recommended path: Article 50 → Evidence → Releases → Distinctions.

For engineers

Start with the executable-worker problem. CGAM treats CLI/cloud agents as bounded workers: they may inspect, patch, test, compare, and report, but they must not become will, memory, authority, judge, or release power.

Recommended path: CGAM → L4 → SER → Self-Evo → Evidence.

For researchers

Start with claim boundaries. The corpus separates architecture, implementation, tested behavior, governance evidence, continuity, authority, safety, personhood, and deployment maturity.

Recommended path: Glossary → Distinctions → c = a + b → L4 → SER → Publications.
